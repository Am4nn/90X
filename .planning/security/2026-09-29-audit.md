# Security audit — 2026-09-29

A fresh-eyes review of the whole app, then the fixes in this branch. Findings are
graded by what a real user or attacker would experience, not by whether the spec
named the input.

| # | Severity | Finding | Where | Fixed? |
|---|---|---|---|---|
| 1 | High | No security headers on any response — no clickjacking protection, no HSTS, no `nosniff`. | `web/next.config.ts` (was empty) | Yes — six headers added and asserted by the break-in HTTP sweep. |
| 2 | High | Solution review, mock scoring and grading call the model with no per-user ceiling; one account can burn the shared monthly budget. | `web/src/app/actions/review.ts`, `web/src/lib/coach/mocks.ts`, `web/src/lib/feed/grader.ts` | Yes — `@/lib/upstash/rate-limit`, fail-closed. |
| 3 | Medium | Cross-user prompt injection via the display name: a controlled name reaches another user's coach prompt. | `web/src/lib/coach/tool-summaries.ts` → `get_friend_summary` | Yes — `sanitizeForPrompt`. |
| 4 | Medium | The coach chat rate limiter fails open, while the lesson limiter fails closed — the split was implicit. | `web/src/lib/coach/rate-limit.ts` | Documented in `SECURITY.md` (kept as-is, on purpose). |
| 5 | Medium | The test sign-in route mints admin sessions and ships in every build; a single misconfigured env could open it. | `web/src/app/api/test/sign-in/route.ts` | Yes — added an explicit `ALLOW_TEST_SIGN_IN=1` opt-in. |
| 6 | Low | `setMinutes` is the only write action with no explicit `viewer.id` scope, relying solely on RLS. | `web/src/app/actions/sync.ts` | Not fixed — safe while the `checkins_owner` policy holds; flagged for a follow-up. |
| 7 | Low | Markdown is rendered without `rehype-sanitize`; AI content can embed external `<img>` tracking pixels. | `web/src/components/markdown.tsx` | Yes — `rehype-sanitize` added and non-`https` image `src` stripped; a `https` tracking image remains possible but the content is source-grounded, not user-uploaded. |
| 8 | Low | Mock scoring had no rate limit. | `web/src/lib/coach/mocks.ts` | Yes — covered by finding 2. |
| 9 | Info | Open-redirect `next` param check rejects `//` but not backslash variants. | `web/src/app/auth/callback/route.ts`, `web/src/app/api/test/sign-in/route.ts` | Not fixed — origin is prepended, low severity. |
| 10 | Info | `setLengthAction` / `setFocusAction` use manual slicing instead of zod. | `web/src/app/actions/plan.ts` | Not fixed — downstream validators bound it. |

## What was already solid

- Every server action calls `requireViewer()` and validates input with zod.
- Admin pages return `notFound()` to non-admins; no existence leak.
- QStash job routes verify the signature against the exact URL.
- No SQL injection: all dynamic SQL goes through Drizzle's parameterized `sql`
  tag.
- The test sign-in gate, the service worker, and the RLS layer are each already
  proven by `check:rls`, `check:coach-tools` and the Playwright suite.

## Not verified here

`check:rls`, `check:tracker`, `check:feed`, `check:friends`, `check:coach-tools`
and `bun run break-in` need a running local Supabase; the lead runs them against
the database in CI.
