# 90x Part 4: Feed — Implementation Plan

> For agentic workers: execute with superpowers:executing-plans (inline), TDD for every pure module, ledger at `.superpowers/sdd/2026-09-27-part4-feed/progress.md`.

**Goal:** A daily card feed that makes you recall, not recognise: typed answers graded against saved key points, spaced repetition per card, a queue that leans on your weak areas, a short diagnostic, in-app flags, and an `/admin` screen where you approve cards in ~15 reviewable batches.

**Architecture:** Pure logic in `web/src/lib/feed/*` (normalize + exact match, score→FSRS rating, queue mix, batch sampling, diagnostic pick), unit-tested. Server: grading service (AI SDK `generateObject` on `fastModel()` = DeepSeek Flash), FSRS via `ts-fsrs`, Redis per-user queue, `ai_usage` + Redis monthly cost meter. UI: `(app)/feed`, `admin/cards`.

**Spec:** `.planning/SPEC.md` §3 (Feed topics, Feed limit, Review timing, Pass mark, Skip, Card quality, AI budget), §6.3, §6.4, §6.5, §6.7, §9. Decisions below override where they differ.

## Decisions from this session (2026-09-27, binding)

- **Multiple choice:** typed first; a **Show options** button turns the card into multiple choice. A correct pick after showing options scores **0.7** (counts as correct, weakest rating). Picking wrong = 0.
- **Flash cards:** typed and AI-graded like typed cards (no self-rate path, except the grading fallback).
- **Output cards:** normalized compare to the stored answer, no AI (spec §6.4.6).
- **Diagnostic:** ~20 mixed cards (4 per area: DSA, Design, CS, Java, SQL) offered on first Feed visit, skippable; its answers count like any review.
- **Batch review:** cards regrouped into **~15 batches (area × part)**; each batch shows you **20 cards chosen riskiest-first** (lowest AI reviewer scores, with its notes) plus random fill; **18/20 good publishes** the batch; a failed batch is marked rejected (regenerated later by the pipeline). AI does the heavy lifting; you do ~15 short reviews.
- **Card mission:** answering any 10 cards (skips don't count) ticks a Today "cards" mission; card slots stop being "coming soon".
- **Grading model:** DeepSeek Flash; exact matches skip AI; schema failure → retry once → self-mark.
- **Offline:** later (follow-up), not in Part 4.

## Global constraints

- Pass mark 70%; skip = 0 and shows the answer; every graded answer updates FSRS state and readiness.
- Only `status = 'live'` cards reach the Feed (drafts visible to admins only, as RLS already enforces).
- Feed topics: DSA patterns, system design, CS, Java, SQL; each toggleable.
- Queue ~30 cards: ~50% weak areas, ~30% due reviews, ~20% new; never two cards in a row on the same topic.
- Unlimited feed; after 20 answers with missions unfinished, a banner points back to Today.
- AI budget $10/month for the group: warn at 80%; at 100% coach/mocks degrade, **grading continues**.
- Card answers (`card_reviews`, `card_state`) are owner-only; friends see nothing of them except aggregate readiness.
- Redis keys `90x:`; design tokens per spec §7; loading/error states like Part 3.

## Review focus

1. Grading output invalid twice → self-mark UI, never a stuck card.
2. Budget at 100% → grading still works; coach-only degradation is recorded, not enforced here (Part 5).
3. Empty queue (all topics off, or everything answered and nothing due) → clear empty state, not a spinner.
4. Two tabs answering the same card → one review each, FSRS state not corrupted (upsert on (user, card)).
5. A flagged/hidden card already sitting in someone's Redis queue is skipped when served.

## Task 1: Schema `supabase/migrations/20260928000009_feed.sql`
- `card_reviews` (id, user_id, card_id, answer text, score real 0–1, points_hit jsonb, outcome correct|wrong|skipped, graded_by match|ai|self|options, used_options bool, created_at). Owner-only RLS.
- `card_state` (user_id, card_id, FSRS fields: stability, difficulty, due_at, reps, lapses, state, last_review) PK (user_id, card_id). Owner-only.
- `card_flags` (user_id, card_id, reason text, created_at) PK (user_id, card_id). Owner insert/select; admins select all.
- `ai_usage` (id, user_id, route, model, tokens_in, tokens_out, cost_usd, created_at). Owner select; server writes.
- `profiles` add `feed_topics jsonb` (null = all on), `diagnostic_done_at timestamptz`.
- `cards` add `hidden bool default false` (flag rule), `risk real` (min reviewer score, for riskiest-first sampling).
- `card_batches` add `label text`, `reviewed_by uuid`, `reviewed_at`; new table `batch_review_items` (batch_id, card_id, verdict good|bad, note) admin-only.
- Extend `check-rls.ts`: friends can't read reviews/state/flags; non-admin can't read batch_review_items. `db:push`, `db:pull`, `db:types`.

## Task 2: Rebatch drafts (pipeline) `pipeline/src/pipeline/cards/rebatch.py` + `pipeline rebatch`
- Regroup existing drafts into ~15 batches: DSA by pattern group (arrays/two-pointers/window/stack · trees/graphs/tries · DP/greedy/intervals · math/bits/design/other), Design (fundamentals · case studies), CS (OS · DBMS · networks · OOP/other), Java, SQL. `label` per batch; `risk` = min(correct, clear, relevant)/5 from `quality`.
- Publish updates to Supabase (reuse `publish.py` card path). Tests with a staging fixture.

## Task 3: Grading core `web/src/lib/feed/grade.ts` (+ `.test.ts`)
- `normalize(text)`; `exactMatch(answer, card)` (answer vs `answer_md` and all key points present) → 1.0.
- `scoreToRating(score, skipped)` → FSRS Again/Hard/Good/Easy (skip or <0.7 → Again; 0.7–0.84 Hard; 0.85–0.99 Good; 1 Easy); options-used caps at 0.7.
- `gradeOutput(answer, card)` normalized compare; `gradeOptions(choice, card)`.
- Server `grader.ts`: `generateObject` with a Zod schema `{ hits: boolean[] }` index-aligned to key points; retry once; else `{ selfMark: true }`. Log tokens/cost to `ai_usage` and the Redis meter (`lib/ai-usage.ts`: `recordUsage`, `monthSpend`, `budgetState()` → ok|warn|over).
- Fixed consistency set `web/scripts/check-grading.ts` (~12 graded answers with expected hit counts; run by hand, not in CI, costs < $0.01).

## Task 4: FSRS + readiness
- `ts-fsrs` wrapper `web/src/lib/feed/srs.ts`: `nextState(prev | null, rating, now)`. Tests: new card, lapse, easy.
- Readiness: area accuracy for Design/CS/Java/SQL (and DSA blended with check-ins) from card scores, last 14 days double (`readiness.ts` gains `cardAccuracy`). Areas with answers now get a score instead of "No data yet".

## Task 5: Queue `web/src/lib/feed/queue.ts` (+ tests) and `web/src/lib/feed/service.ts`
- Pure `buildQueue({ due, weak, fresh, topicsOn, size: 30 })`: 50/30/20 mix, no same topic twice in a row, backfills when a pool runs short, deterministic given a seed.
- Weakness per topic from `card_state` lapses and recent scores + DSA pattern mastery; importance from topics/problems.
- Service keeps `90x:feed:<user>` (Redis list); `nextCard(userId)` pops, skips hidden/non-live, refills below 10.

## Task 6: Feed UI `web/src/app/(app)/feed/*`
- One card: area dot + topic, difficulty, prompt (markdown), textarea, **Skip** / **Check**; mcq has **Show options**.
- Result: score, key points hit/missed, the answer, source link; **Next**. Self-mark fallback (Got it / Missed it).
- "Why this card" line (weak area / due review / new); **Report** (flag with reason).
- Topic toggles (chips) in a sheet/popover; desktop side panel: session progress + why.
- Banner after 20 answers when Today has open missions. Loading/error/empty states.

## Task 7: Today integration
- Planner: cards slots become normal `open` missions ("10 cards"); `onCardAnswered` ticks one cards mission per 10 non-skip answers today; day status counts them. Update Part 3 tests that assumed coming_soon.

## Task 8: Diagnostic
- `pickDiagnostic(pool)` (4 per area, mixed difficulty) pure + test; first-visit prompt on Feed ("15 minutes, 20 cards · Start / Skip"); progress bar; results summary per area; sets `diagnostic_done_at`.

## Task 9: Flags + hiding
- Report → `card_flags`; server increments `flag_count`; 2 flags → `hidden = true`. Nightly (hourly job at local midnight of the admin, or a daily step in the hourly route): cards skipped by every answerer and zero correct in 14 days → hidden. Hidden cards leave queues.

## Task 10: `/admin/cards`
- Batches list: label, cards, AI pass rate, status, progress. Batch review: 20 cards (riskiest-first + random), each with AI reviewer scores/notes, Good/Bad (+ note), keyboard shortcuts (G/B, ←/→). At 20 verdicts: ≥18 good → batch + its cards `live`; else `rejected`.
- Flagged queue: hidden cards with reasons → Keep (unhide) / Retire.
- Admin-only (`is_admin()`), loading/error states.

## Task 11: Verification + review
- `typecheck`, `lint`, `test`, `format:check`, `check:tokens`, `check:dead`, `build`, `check:rls`, `check:tracker`; `check:grading` by hand.
- Live: approve 1 batch → Feed serves its cards → typed answer graded, key points shown → FSRS due date set → 10 answers tick Today's card mission → readiness area gets a score → flag twice hides the card.
- Fresh whole-branch review, fix Critical/Important, deferred minors listed.
